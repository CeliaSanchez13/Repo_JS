🔹Sincronía

    - El código se ejecuta línea por línea, en orden.

    - Cada instrucción bloquea la ejecución hasta que termina.

    - Si una tarea tarda mucho, detiene todo el flujo.

📌 Ejemplo: código sincrónico

console.log("Inicio");

function sumar(a, b) {
  return a + b;
}

const resultado = sumar(3, 5);
console.log("Resultado:", resultado);

console.log("Fin");


📤 Salida en consola:

Inicio
Resultado: 8
Fin


➡️ Todo ocurre en orden, no hay espera ni tareas en paralelo.

---------------------------------------------------------------------------

🔹 Asincronía

Permite que algunas operaciones (como lecturas de archivos, solicitudes HTTP, timers, etc.) no bloqueen la ejecución.

El programa puede continuar mientras la tarea termina “en segundo plano”.

JavaScript maneja esto con callbacks, promesas y async/await.

📌 Ejemplo: código asincrónico con setTimeout

console.log("Inicio");

setTimeout(() => {
  console.log("Esto aparece después de 2 segundos");
}, 2000);

console.log("Fin");


📤 Salida en consola:

Inicio
Fin
Esto aparece después de 2 segundos


➡️ Aunque setTimeout tiene 2 segundos de espera, el resto del programa sigue ejecutándose.

------------------------------------------

| Concepto   | Sincronía                                | Asincronía                                                            |
| ---------- | ---------------------------------------- | --------------------------------------------------------------------- |
| Ejecución  | Línea por línea, bloqueante              | No bloquea, puede esperar tareas                                      |
| Uso típico | Operaciones rápidas (sumas, logs, loops) | Operaciones que tardan (peticiones HTTP, lectura de archivos, timers) |
| Ventaja    | Simplicidad                              | Flujo no bloqueado, mejor rendimiento                                 |
| Desventaja | Bloquea si algo tarda mucho              | Requiere manejar callbacks/promesas                                   |
